# AK Labs OS — Architecture & Governance

This file is the constitution for AK Labs OS. It exists so architectural
decisions live in the repo, not in chat history — see Principle 3 below;
this document is itself an application of it.

## Core Vision

AK Labs OS is not an AI coding assistant. It is a persistent AI
Engineering Organization. Coding is one capability within that
organization, not the whole of it. The long-term goal: the founder
provides a product idea or business objective, and the organization
coordinates planning through implementation with minimal manual
prompting.

Every architectural decision should be evaluated against this vision.

## Architectural Principles

**1. Separate capabilities from model providers.**
Policies reference engineering capabilities, never model names.
Providers and models must remain replaceable without touching
engineering workflows. (Implemented: `capabilities.yaml` +
`capability_router.py`.)

**2. Decisions must be evidence-driven.**
No confidence scores generated by an LLM about itself. Confidence is
computed from measurable evidence: validation success, retries,
reviewer findings, test results, historical execution data, artifact
verification. Self-reported confidence is not implemented, ever.

**3. Build organizational memory, not conversation memory.**
Historian evolves from recording events into capturing organizational
knowledge: repeated decisions, recurring architectural choices,
engineering standards, project outcomes, lessons learned. Historian
surfaces candidates. It never applies autonomous policy changes.
Humans always approve permanent standards.

**4. Build organizational culture.**
A knowledge layer of engineering principles shared by every
department: coding standards, architecture patterns, preferred stack,
anti-patterns. Organization-wide references, not project-specific
memories. (Implemented: `culture.yaml`, first draft — AK's to edit.)

**5. Workflow over prompting.**
Long-term objective: reduce manual prompt orchestration. Departments
communicate through structured Work Orders, explicit handoff protocols,
and shared context, not the founder re-explaining project state each time.
(Implemented foundation: `work_orders/`. Planned next: Engineering
Transaction Protocol as v0.4.2 Department Handoff Infrastructure.)

**6. Preserve separation of responsibilities.**
Each department has one primary responsibility. Avoid expanding an
existing agent into a multi-purpose agent. Improve coordination
between single-purpose agents instead of increasing any one agent's
individual intelligence.

**7. Favor explicit architecture over clever abstractions.**
Small systems stay readable. Delay inheritance, ownership metadata,
or similar abstractions until they provide measurable value.

**8. Maintain canonical ownership.**
Every engineering concern has exactly one canonical owner. Work Orders own
engineering state. The planned Engineering Transaction Protocol owns ownership
transfer. Historian owns historical records. Validation Harness owns validation
results. Policy Engine owns policy enforcement. Safe Artifact Writer owns
artifact persistence.

## Immediate Development Rule

Next milestones strengthen the organization itself, not code
generation quality. Priority order:

1. Organizational memory
2. Workflow coordination
3. Engineering governance
4. Project management
5. Decision traceability

over adding new coding capabilities. When a design decision is
ambiguous, choose the option that moves AK Labs OS closer to
functioning like a real engineering organization, not a coding
assistant.
